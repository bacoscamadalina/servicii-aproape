# Provider offerings quality bar

- Direction contract: the private provider dashboard remains a controlled workshop;
  the new service-area workbench follows the existing warm mineral paper, blue-steel
  panels, Nimbus Narrow headings, Carlito copy and one ochre primary action.
- Product boundary: services are provider declarations limited by current authorized
  ONRC categories; coverage is exact SIRUTA and never inferred from registered office.
  The aggregate remains private and unverified.
- State coverage: authorized selected, unauthorized disabled, empty coverage, saved
  coverage removal, source failure, validation error, stale-revision conflict and
  identical no-op are represented in code/tests.
- Progressive enhancement: county/locality selection works through a GET reload
  without JavaScript and uses an abortable dependent selector with `aria-live` when
  JavaScript is available.
- Responsive evidence: desktop 1454×1000 and mobile 391×845 show no horizontal
  overflow; self-hosted fonts report loaded.
- Detector: run exactly once after UI changes. It ran in degraded regex mode because
  parser modules were unavailable; findings were advisory type-ramp/palette drift,
  mostly pre-existing, with no blocking anti-pattern reported.
- Automated evidence: 108 Django tests pass locally (4 intentional skips); all 11
  offering tests pass on PostgreSQL, including the two-connection revision race.
